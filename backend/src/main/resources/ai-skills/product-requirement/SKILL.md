# 目标

根据用户需求与资料，整理一份产品需求草案树（标题大纲）：以产品目标为根，围绕「目标 → 用户 → 范围 → 风险 → 里程碑」逐层展开。

# 结构模型

产品需求是一棵以产品目标为根、按需求维度逐层展开的树。本阶段只输出标题大纲（# 到 ##### 标题行），后端会按标题层级确定性生成图形节点与连线：

- `#` → 产品目标（ellipse 中心）
- `##` → 需求维度（rectangle 一级分支：目标 / 用户 / 范围 / 风险 / 里程碑）
- `###` 及以下 → 各维度下的具体条目（oval 叶子）
- 父到子连线统一为曲线（curve），呈放射状布局

# 内容规范

1. 目标先行：以产品的核心目标或要解决的问题为唯一根节点，一句话点明价值。
2. 维度完整：一级分支覆盖目标、用户、范围、风险、里程碑五个维度，维度之间互斥且穷尽（MECE）。
3. 用户具体：用户维度写明目标用户画像、痛点与使用场景，不写「普通用户」这类空泛描述。
4. 范围清晰：范围维度区分「本次要做」与「本次不做」，明确功能边界。
5. 风险可识别：风险维度列出主要风险（技术、进度、资源等）及简要应对方向。
6. 里程碑可度量：里程碑维度写明阶段交付物与时间节点，可验证。
7. 标题精炼：每个标题 8-16 字，是有实质信息的短语，禁止「概述」「介绍」等空泛词和单个词。

# 输出

只输出 # 到 ##### 标题行（Markdown 标题大纲），不要输出任何正文、列表、前言、解释或代码围栏。
