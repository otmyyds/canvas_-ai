# 目标

根据用户需求与资料，生成一张规范、可读的流程图（图形节点 + 连线）。

# 图形元素与含义

画布支持四种图形节点（shape 字段）与一种连线（connect 动作），各元素职责如下：

## ellipse（椭圆）—— 开始/结束点

标识流程的起点与终点。
- 一个流程有且仅有一个开始节点（id 用 start1，shape=ellipse）。
- 结束节点（shape=ellipse）可有多个，对应不同分支的出口。
- 标题居中，如「开始」「结束」。

## rectangle（矩形）—— 处理步骤

表示一个具体的操作或工作步骤。
- 标题写成精炼的动词短语，如「提交订单」「审核数据」。
- 同一流程中处理步骤的标题风格保持一致。

## diamond（菱形）—— 判断/决策点

表示需要做出选择或判断的节点。
- 标题写成「是否…」「…选择」等疑问或选择形式，如「是否通过审核？」。
- 每个判断节点至少分出两条分支，并在连线 label 上写明分支条件。

## oval（胶囊）—— 输入/输出、存储与其他

表示没有独立形状的语义节点。
- 输入/输出：标题注明「输入：…」「输出：…」。
- 文档/数据库存储：标题注明存储对象，如「数据库：订单表」。
- 子流程/手动干预：标题注明「子流程：…」「人工审批：…」。

# 连线规范

- 连线用 connect 动作，单向箭头，从上一节点指向下一节点，指示流程方向。
- 流程图优先用直线（style=straight）；回连或旁支可用曲线（style=curve）。
- 从判断节点分出的每条连线必须写 label，标明分支条件（如「是」「否」「线上」「线下」）。
- 不同分支走几步后可汇合到同一节点（多条 connect 指向同一 toShapeId）。

# 结构规范

1. 如果从原文中找出判断、条件、选择、并列（「或者/或」「以及」），生成的流程要有分支，不能是一条直线，用 diamond 分出不同后续节点。
2. 逻辑清晰：按实际执行顺序排列，避免循环和死胡同；允许分支汇合。
3. 简洁明了：用最少节点和文字描述流程，标题 8-16 字，避免冗余。
4. 一致性：同类元素用同一 shape（开始/结束用 ellipse，判断用 diamond，步骤用 rectangle）。
5. 节点数量按内容实际需要（一般 8-16 个），不要为凑直线而合并步骤。

# 输出

只返回通过校验的画布动作（create_shape + connect），格式遵循 boardActionInstruction 的 JSON 规范。
